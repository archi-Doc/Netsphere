# Performance and coverage review

Measured on September 9, 2026, against baseline `eaaf676`, using .NET SDK 10.0.401, runtime 10.0.12, and Windows 11 x64 (build 26200).

## Changes

- Moved connection-response and disposal-callback closures into helpers called only when needed. Ordinary control-packet dispatch and callback-free disposal no longer allocate closure objects.
- Return immediately for ACKs received after a send transmission has been disposed; the locked validation remains for live transmissions.
- Traverse relay links directly during cleanup and rebuild encryption snapshots only after membership changes. Relay diagnostics use an indexed response array instead of a concurrent dictionary; each worker writes a distinct slot, and formatting waits for all workers.
- Generated byte-memory responses reuse an exclusively owned request buffer when it fits. Shared buffers and larger responses are copied before the input lease is returned. Overlapping slices are supported. Ordinary generated responses no longer emit ownership-transfer flags; pooled responses retain them.
- Removed unused filter-definition generation, an unused generator dictionary, impossible null checks after filter construction, empty relay result branches, and an unused empty termination method.
- Fixed one-byte result serialization exposing the pool's full buffer length, length-prefixed serialization failing to dispose its writer, and relay encryption ignoring a packet slice's offset or tag capacity. Signature verification now uses the writer-owned span so cleanup also runs if verification throws.
- Updated English XML documentation and README guidance on ownership, filter lifetimes, streaming, cancellation, generated-code compatibility, and measurement limitations.

Existing commented-out code was retained, including complete block comments and standalone historical code comments. The removed executable generator method was unreferenced.

## Measurements

Release builds, 10,000 warm-up operations per case, seven samples, median reported. Allocations use `GC.GetAllocatedBytesForCurrentThread`; setup and JSON output are outside the timed loops.

| Operation | Before, ns/op | After, ns/op | Before, B/op | After, B/op |
| --- | ---: | ---: | ---: | ---: |
| Receive unmatched ping response | 141.19 | 132.75 | 64 | 0 |
| Create and dispose receiver without callback | 95.47 | 86.55 | 208 | 176 |
| Dispose receiver again | 69.29 | 64.43 | 32 | 0 |
| Clean unchanged empty relay circuit | 139.74 | 49.43 | 128 | 0 |
| Process duplicate burst ACK after disposal | 28.91 | 11.54 | 0 | 0 |

In the same final run, the previous rent/copy/return response strategy took 73.56 ns for 1 KiB; reuse took 48.68 ns, a 33.8% reduction. Both allocated zero managed bytes after pool warm-up. Reuse avoids pool operations, rather than removing a managed allocation on every warmed call.

Raw samples:

- [before.json](tools/CoreBenchmarks/before.json): initial baseline for transmission and relay cases.
- [packet-before.json](tools/CoreBenchmarks/packet-before.json): control-packet baseline, measured after the other optimizations but before extracting the connection-response closure. Its other rows are intermediate results.
- [after.json](tools/CoreBenchmarks/after.json): final optimized cases and the response-strategy comparison.

IPv4 formatting, packet creation, and 1 KiB encryption remained allocation-free after warm-up. Small timing differences in unchanged code are measurement variation, not claimed improvements.

These microbenchmarks do not measure end-to-end throughput, cold pool misses, worker-thread allocations, or tail latency. Receivers, async operations, filters, copied client responses, and large transmission windows still allocate. No claim is made that the whole library is allocation-free or that every workload is faster.

## Coverage and regression tests

Collected Debug coverage with `dotnet-coverage` 18.11.0. Source lines are merged across async state machines; generated files are excluded from the runtime total and reported separately for RPC code in the test assembly.

| Scope | Before | After |
| --- | ---: | ---: |
| Handwritten Netsphere runtime | 6,923 / 10,948 (63.24%) | 7,015 / 10,973 (63.93%) |
| Generated RPC frontend and backend in xUnitTest | 975 / 1,515 (64.36%) | 940 / 1,442 (65.19%) |
| NetHelper | 128 / 332 (38.55%) | 160 / 333 (48.05%) |
| RelayCircuit | 125 / 198 (63.13%) | 148 / 194 (76.29%) |
| TransmissionContext | 76 / 119 (63.87%) | 93 / 136 (68.38%) |
| RelayHelper | 43 / 50 (86.00%) | 47 / 54 (87.04%) |

Source totals changed because code was added and removed, including simplification of generated methods. Background maintenance and timeout scheduling can change a small number of covered lines between runs; percentages are observations from the final run, not deterministic test assertions.

Added 25 cases covering one-byte result encoding, invalid result lengths, length prefixes, serialization failures after buffer growth, signature salt/tampering, relay slice encryption and insufficient tag capacity, exclusive/shared/overlapping response buffers, unchanged and closed relay circuits, and generated byte-array/Memory/ReadOnlyMemory responses. A regression test bounds allocations across repeated serialization failures to detect loss of the grown pooled buffers while allowing exception allocations.

Validation completed:

- Full solution builds in Debug and Release: zero warnings and errors.
- All 244 tests pass in both configurations; no skipped cases.
- Emitted frontend/backend code inspected for response ownership, copying, cleanup, and filter construction.
- `git diff --check` passes; existing commented-out blocks and standalone comments were compared against the baseline.

Coverage gaps remain in stream conversion and connection-discovery helpers, relay failure combinations, platform-specific utilities, and background maintenance. Generated RPC coverage exercises emitted runtime behavior; it is not unit coverage of all generator diagnostics. Network loss/reordering combinations, long-running contention, and sustained allocation behavior need separate stress workloads. Raising aggregate line coverage alone would not establish those properties.

## Reproduction

Use the build, coverage, and benchmark commands in [README.md](README.md#building-and-testing). Run network tests and benchmarks sequentially because they use the diagnostic terminal. Coverage XML and logs are written under ignored `artifacts/`; the small benchmark JSON files above are retained for comparison.
